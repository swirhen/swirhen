概要
- FastAPI + React/Vite のtorrent管理画面。
- Apache配下の /torrent-admin/ から配信。
- APIはsystemdの torrent-admin-api.service で稼働。
- 認証はFastAPIのログイン画面。Cookieセッションは180日保持。VS Code等の内部ブラウザ（サードパーティCookie制限環境）向けにBearerトークン/localStorage併用認証にも対応。

主なファイル
- web/api.py: 認証、feed取得、削除、Undo。
- web/src/main.tsx: React画面、検索、カテゴリ、日付、選択、削除、Google検索。
- web/src/styles.css: 画面スタイル。
- web/release.sh: フロントビルドとAPI再起動。
- web/requirements.txt: FastAPI実行に必要な依存関係。requestsを追加済み。
- make_nyaa_db.py: 参考DDLコメントにfeed_dataのインデックス定義を記載。

現在の機能
- URLの ?c=av でカテゴリ初期絞り込み。
- カテゴリボタン選択時にURLのcも再読み込みなしで同期。
- カテゴリ順: av, doujin, manga, pictures, game, anime, comic, music, live。
- av/doujin/manga/pictures/gameは薄いピンク。それ以外は緑。
- 表中カテゴリもクリックで絞り込み可能。
- 表タイトル横の小さいGボタンでタイトルをGoogle検索。タイトル文字自体は検索ボタンではない。
- URLリンクは現在のタブで開く。
- 開始日・終了日は個別入力、各欄のxで個別クリア。
- 取得日時は画面上では秒を表示せず分まで。
- (統合済み) 以前は最新DBと過去DBをヘッダーのリンクで切り替えていたが、過去DBは現行DBへ統合したため廃止。ソース切り替えUI・APIのsourceパラメータは撤去。
- 検索ボックスは半角スペースでAND、|でOR。先頭が-の語は除外。
- 検索キーワードはURLの?q=へ同期し、特殊文字はURLエンコード。
- 保存した検索条件をJSONへ保存し、上部ページネーション左側のプルダウンから呼び出せる。
- ページネーション上部は保存操作を左、ページ操作を右に配置。下部はページ操作のみ。
- 画面右上に手動更新ボタンを配置。検索条件を維持して一覧を再取得する。
- URL列にブラウザ用ダウンロードとサーバー保存の2ボタンを配置。
- サーバー保存は確認なしで実行し、結果を右上トーストへ表示。6秒後にフェードアウトして消える。
- トースト表示中に続けて保存すると、ファイルリストへ結果を追記する。
- 一括ダウンロードは選択項目をサーバー側でカテゴリ別に保存し、完了モーダルへ結果を表示する。
- 一括ダウンロードではDBのdownload_dirおよびdownload_failed_atを更新しない。
- タイトル(た、種ぇぇ)のすぐ右に年絞り込みの複数選択プルダウンを配置。
  - ボタンラベルは常に「検索対象」固定。開いて選択しても閉じればラベルは戻る（選択値は保持）。
  - 選択肢はDBに実際にデータが存在する年だけを列挙（MIN/MAX+年ごとのEXISTSで高速に判定）。
  - 飛び飛びの複数年選択可（2024,2026のみなど）。ボタン右のサマリー表示に選択中の年をカンマ区切りで表示（未選択はall）。
  - 選択は web/year_filter.json へシステム全体で永続化（プルダウンを閉じた時にPUT /api/year-filterで保存）。
  - 検索への反映はcreated_atの年範囲をORで結合しdate_from/date_toとはANDで併用。idx_feed_data_created_atが引き続き有効。
  - (修正済み) get_available_years()はMIN(created_at)とMAX(created_at)を一つのSELECTで同時取得しておりSQLiteのMIN/MAX最適化が効かず全件スキャンになっていた（/api/feed-data呼び出し毎に約83msのオーバーヘッド）。MIN/MAXを別クエリに分けて0.9ms程度へ改善済み。
- 年絞り込みはチェック中の一時選択と適用済み選択を分離し、プルダウンを閉じた時にだけ検索・保存を実行する。

DB統合とパフォーマンス改善
- api.pyのDB配置先はwebディレクトリの親、torrentsearch/。DBは nyaatorrent_feed.db の1本のみ。
- nyaatorrent_feed_before_2023.db（過去DB、312,008件）の全レコードをnyaatorrent_feed.db（統合前722,530件）へINSERT OR IGNOREで統合済み（linkのunique制約により重複0件、統合後1,034,538件）。
- 統合前にnyaatorrent_feed.dbをnyaatorrent_feed_premerge_backup.dbとしてバックアップ済み（.gitignore対象、実DBと同様Git管理外）。
- nyaatorrent_feed_before_2023.db自体は削除せず現状のまま残置（未使用ファイルとして温存）。
- 検索の日付絞り込み(date_from/date_to)は、これまで`date(created_at) >= date(?)`のように列を関数でラップしており、インデックスが一切効かず全件走査になっていた（絞り込みなしと同程度の235ms前後）。
- `created_at >= ?` / `created_at <= ?`の直接比較へ修正し、新規インデックス`idx_feed_data_created_at`をfeed_data(created_at)へ追加（make_nyaa_db.pyの参考DDLにも追記済み）。
- 実DBで実測: 日付のみ絞り込み+複合語検索が旧実装237ms→修正後85ms程度（統合後の103万件規模でも同等の効果を確認）。
- カテゴリ絞り込みは既存のidx_feed_data_category_pubdate等が効くため元々高速（約73ms）。
- ローカルAPI経由で date_from=2022-01-01/date_to=2022-12-31 を指定し、統合前は過去DBにしかなかった2022年データ(191,872件)が現行DBだけで取得できることを確認済み。
- 実 DBで available_years は [2021, 2022, 2023, 2024, 2025, 2026] と確認済み。years=2024&years=2026 指定で351,541件へ絞り込みを確認済み。

設定ファイル
- web/download_settings.json: ルートディレクトリとカテゴリ別保存先。個人設定のためGit管理外。
- web/search_conditions.json: 保存した検索条件。個人設定のためGit管理外。存在しなければAPIが作成する。
- web/year_filter.json: 選択した年絞り込み（例: {"years": [2024, 2026]}）。個人設定のためGit管理外。存在しなければAPIが作成する。
- カテゴリ別保存先が空欄の場合はルートディレクトリへ保存する。
- 保存先は `root_dir / category_dirs[category]`。パスはPythonのPathで処理するため半角スペースを含められる。

注意
- release.shはVITE_BASE_PATH=/torrent-admin/でビルドする。
- 認証環境変数は/etc/default/torrent-admin-apiの
  TORRENT_ADMIN_USERNAME / TORRENT_ADMIN_PASSWORD / TORRENT_ADMIN_SECRET。
- 実環境へ反映する前に、`requests`を含むrequirements.txtを本番仮想環境へインストールすること。
- 本番のnyaatorrent_feed.dbにも同様のDB統合（過去DBのINSERT OR IGNORE）とidx_feed_data_created_atインデックス追加を実施すること。本番でのバックアップ取得後に作業する。
- ローカルデバッグではtorrentsearch/idpass.txtの1行目をID、2行目をパスワードとして読める。
- idpass.txtは.gitignore対象。実際の認証情報はコミットしないこと。
- ローカルデバッグ開始時は、まずtorrentsearch/idpass.txtが存在することだけ確認する。内容は表示・ログ出力しない。
- API起動（ターミナル1）: `cd checker/torrentsearch/web` → `python -m uvicorn api:app --reload --host 127.0.0.1 --port 8000`
- Vite起動（ターミナル2）: `cd checker/torrentsearch/web` → `npm.cmd run dev`
- ブラウザ: `http://127.0.0.1:5173/`。Viteが/apiを8000番へプロキシする。
- 終了時はAPIとViteの各ターミナルでCtrl+C。デバッグ開始前にidpass.txtの実値を確認して入力する。
- 変更後はnpm.cmd run buildとpython -m py_compile api.pyを実行する。
